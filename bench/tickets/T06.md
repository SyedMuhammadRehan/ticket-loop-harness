# T06: Let customers combine discount codes

Today an order takes one code. Trade customers hold a percentage code and often a welcome or
loyalty voucher as well, and want to use them together.

## Acceptance criteria

1. An order accepts `codes`, a list of discount codes. The existing single `code` keeps
   working and means the same as a list of one.
2. At most one percentage code per order. A second one is refused with code
   `ONE_PERCENT_CODE`.
3. The percentage code is applied first, to the subtotal. Fixed codes are then applied in the
   order given, each to what is left.
4. The total discount never exceeds the subtotal: a fixed code takes only what remains.
5. The same code twice is refused with code `DUPLICATE_CODE`. An unknown code is still
   `UNKNOWN_CODE`.
6. The order records each applied code with the amount it took, in the order applied, and
   `discountCents` is their sum. Tax is charged on the subtotal less the total discount.
7. A refused order reserves no stock.
8. Over HTTP, `POST /orders` accepts `codes`, and the two new refusals are a 422, like an
   unknown code.

## Out of scope

- New kinds of discount, per-product discounts, expiry dates.
